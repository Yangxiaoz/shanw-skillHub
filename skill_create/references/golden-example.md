# 黄金示例：job-intel（销售求职背景调查）

skill-create 的制作思想对齐对象。制作任何 skill 前先读本文件与 `../../job_search/SKILL.md`（正本），再动笔。

## job-intel 的八项设计机制

### 1. 触发词机制 — 精准的调用边界

- description 内嵌具体触发短语（「对 XX 公司做背景调查（求职用）」），触发条件具体到能被识别
- 声明与既有 skill 的优先级（取代 company-sales-intel，两者同时命中优先用本 skill）
- 触发词 ≠ 泛化的「当用户需要时」——泛化触发词会让 skill 被误触发或漏触发

### 2. 固定产出结构 — 确定性优先

- 八章结构顺序不可乱（速览 → 一 → … → 七 → 尾注），排序逻辑显式写明（业务层层递进，竞品章必须在场景之后、大盘之前）
- 固定结构让每次产出可预期、可校验——它是审查闸门 A3 类规则的判据来源

### 3. 草稿 ≠ 终稿

- Step 3 明确「此步产物只是草稿，禁止直接 present」，交付必须依次过闸门
- 防止把中间产物当成品交付

### 4. 输出审查闸门 — 核心设计

- 五类校验：A 结构/语法（脚本自动化）、B 逻辑一致性、C 请求一致性、D 事实/口径、E 边界与歧义
- 错误分级 P0（拦截/澄清）/ P1（修后重审）/ P2（修正即过），每级有明确处理策略
- 双轨校验：自动化脚本（仅标准库，agent 直接调用）+ LLM 按清单逐项自审
- 降级输出：宁可不交付，不交付错的——输出诚实声明（已确认 / 被拦截 / 需澄清 / 越界说明），声明自身还要过最小自审
- 审查记录：每次生成留 JSON 日志（checks_run、逐条结果、final_outcome）

### 5. darwin 回流机制 — 失败沉淀为规则

- 每次审计根因回写为「防复发铁律」（如「数据时效锚定最新官方源」「跨产品线叙事不错配」），标注来源
- skill 是活的文档，随迭代变厚，同类错误不复发

### 6. 内容铁律 — 迭代沉淀的偏好

- 去 AI 味（最高优先级）：不堆形容词、不搞花哨栏目、平实像内部 brief
- 口径纪律：每个数字标来源类型（公司公开口径 / 第三方统计 / 媒体测算），三类必须分清
- 视角纪律：外部求职者视角，不越界写内部信息，洞察用客观表述

### 7. 黄金示例（worked example）

- references/ 放完整成品（火山引擎手册 2026-08 版），「结构、口径标注、竞品四列表、版式全部照此对齐」

### 8. 与既有 skill 的关系 — 显式版本管理

- 声明取代旧 skill、冲突时谁优先，避免 skill 库膨胀后互相打架
